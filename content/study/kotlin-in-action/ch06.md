## 이 장에서 남은 것

- 컬렉션을 도는 루프 대부분은 **표준 라이브러리 함수 하나와 람다**로 바뀐다. 함수는 돌려주는 모양으로 고른다 — 새 컬렉션이면 `filter`·`map`, 값 하나면 `reduce`·`fold`, 참·거짓이면 `all`·`any`.
- 리스트를 맵으로 바꿀 때는 **람다가 키를 만드는지 값을 만드는지**를 본다. `associateBy`는 람다가 키, `associateWith`는 람다가 값이고 `groupBy`는 같은 키의 원소를 리스트로 모은다.
- `windowed`는 겹치게, `chunked`는 겹치지 않게 자르고 `zip`은 **짧은 쪽 길이에 맞춘다.** 결과 길이가 원본과 다르다는 걸 알고 쓴다.
- 시퀀스는 중간 컬렉션 없이 **원소를 하나씩 연산 끝까지 흘려 보낸다.** 최종 연산을 부르기 전에는 아무것도 계산하지 않는다.

## `filter`·`map`은 새 컬렉션을 만들고, `reduce`·`fold`는 컬렉션을 값 하나로 접는다

컬렉션을 직접 돌면서 조건을 걸고 결과를 모으던 코드는 대부분 표준 라이브러리 함수에 람다를 넘기는 한 줄이 된다. 가장 자주 쓰는 넷은 결과의 모양으로 갈린다.

- **`filter`** — 원소마다 람다를 불러 `true`를 돌려준 원소만 모아 새 컬렉션을 만든다. 고르기만 하고 원소를 바꾸지는 않는다. `list.filter { it % 2 == 0 }`
- **`map`** — 원소마다 함수를 적용하고 그 결괏값을 새 컬렉션에 모은다. 원소 수는 그대로고 원소가 바뀐다. `list2.map { it * it }`
- **`reduce`** — 컬렉션을 값 하나로 접는다. 첫 번째 원소를 누적 값으로 넣고 두 번째 원소부터 람다에 누적 값과 원소를 넘겨 새 누적 값을 받는다
- **`fold`** — `reduce`와 같지만 누적 값을 첫 원소가 아니라 직접 정한 시작 값에서 시작한다
- **`runningReduce`·`runningFold`** — 마지막 값만이 아니라 중간 누적 값 전체를 리스트로 돌려준다

`reduce`와 `fold`는 시작 값 하나 차이인데 그 차이로 결과 타입이 갈린다.

```kotlin
val list3 = listOf(1, 2, 3, 4)
val summed = list3.reduce { acc, element -> acc + element }
// ...
val folded = people.fold("") { acc, person -> acc + person.name }
```

`reduce`의 누적 값은 첫 원소에서 시작하니 원소 타입을 벗어나지 못한다. `Int` 목록을 접으면 `Int`가 나온다. `fold`는 시작 값을 `""`로 줬으니 누적 값이 `String`이고 `Person` 목록이 이름을 이어 붙인 문자열 하나가 된다. **원소와 다른 타입으로 접으려면 `fold`다.**

여기까지는 원본을 그대로 두고 새 컬렉션이나 값을 돌려준다. 원본을 그 자리에서 바꾸는 함수는 가변 리스트에 따로 있다.

- **`replaceAll`** — `MutableList`의 모든 원소를 람다의 결과로 바꾼다. `names.replaceAll { it.uppercase() }`이면 `names`가 `[DMITRY, JOHN]`이 된다
- **`fill`** — 가변 리스트의 모든 원소를 같은 값 하나로 채운다. `names.fill("Dmitry")`이면 `[Dmitry, Dmitry]`

## 술어를 넘기면 컬렉션에 던지는 질문이 되고, 답의 모양은 함수가 정한다

- **술어(predicate)** — `Boolean`을 돌려주는 람다. 원소 하나를 받아 조건을 만족하는지 답한다

`val canBeInClub = { p: Person -> p.age <= 23 }`를 한 번 만들어 두고 받는 함수만 바꾸면 같은 조건으로 다른 질문을 한다. **조건은 람다에 고정하고 질문은 함수 이름으로 바꾼다.**

- **`all`** — 모든 원소가 술어를 만족하는가. `Boolean`
- **`any`** — 만족하는 원소가 하나라도 있는가. `Boolean`
- **`none`** — 만족하는 원소가 하나도 없는가. `Boolean`
- **`count`** — 만족하는 원소가 몇 개인가. 개수
- **`find`** — 만족하는 첫 번째 원소. 없으면 `null`
- **`partition`** — 만족하는 그룹과 만족하지 않는 그룹. 리스트 두 개의 쌍이라 `val (comeIn, stayOut) = people.partition(canBeInClub)`처럼 구조 분해로 받는다

`people`이 23살 Dmitry와 29살 John이면 `all`은 `false`, `any`는 `true`, `none`은 `false`, `count`는 1, `find`는 Dmitry다. 조건은 하나인데 답은 참·거짓, 개수, 원소, 리스트 쌍으로 다 다르다. 컬렉션에 어떤 불변 조건이 성립하는지 확인하는 일이 이름 하나로 끝난다.

## 맵을 만드는 함수는 람다가 키를 만드느냐 값을 만드느냐로 갈린다

평평한 리스트를 기준에 따라 맵으로 구조화하는 함수가 넷이다. 람다가 맵의 어느 자리를 채우는지만 기억하면 된다.

- **`groupBy`** — 람다 결과가 키, 그 키를 가진 원소들의 리스트가 값이다. 원소를 어떤 특성에 따라 여러 그룹으로 나눌 때 쓴다
- **`associate`** — 람다가 `키 to 값` 쌍을 만든다. 키와 값을 둘 다 직접 정한다
- **`associateWith`** — 원소가 키, 람다 결과가 값이다
- **`associateBy`** — 람다 결과가 키, 원소가 값이다

`groupBy`와 `associateBy`는 같은 람다로 키를 만들어도 값의 모양이 다르다.

```kotlin
println(people.groupBy { it.age })
// {23=[Person(name=Dmitry, age=23)], 29=[Person(name=John, age=29)]}
val ageToPerson = people.associateBy { it.age }
println(ageToPerson)
// {23=Person(name=Dmitry, age=23), 29=Person(name=John, age=29)}
```

`groupBy`의 값은 리스트라서 같은 나이가 여럿이어도 전부 담긴다. `associateBy`의 값은 원소 하나다. 원소를 그룹으로 묶지 않고 키 하나에 원소 하나를 대응시킬 때 `associate` 계열을 쓴다.

람다가 쌍을 돌려줄 때 함수를 잘못 고르면 맵 모양이 통째로 바뀐다.

```kotlin
val nameToAge = people.associateBy { it.name to it.age }
println(nameToAge)
// {(Dmitry, 23)=Person(name=Dmitry, age=23), (John, 29)=Person(name=John, age=29)}
```

`associateBy`는 람다 결과를 키로 쓰니 `it.name to it.age` 쌍이 그대로 키가 되고 값은 `Person`이다. 이름을 키로, 나이를 값으로 만들려면 같은 람다를 `associate`에 넘겨야 `Dmitry=23` 모양이 나온다. **쌍을 만드는 람다는 `associate`, 키만 만드는 람다는 `associateBy`다.**

[[TIL-260415-redis-lua-coupon-issue|Redis Lua 선착순 쿠폰 발급]]의 `IssueResult`가 `entries.associateBy { it.code }`로 Lua 반환 코드에서 enum 상수를 찾는 맵을 만든다. 키는 람다가 꺼낸 `code`, 값은 상수 자신이다.

## 묶고 짝짓고 펼치는 연산은 결과 길이가 원본과 다르다

`map`은 원소 수를 그대로 두지만 인덱스나 내포 구조를 다루는 연산은 결과 길이가 바뀐다. 길이가 어떻게 바뀌는지가 곧 그 함수의 규칙이다.

- **`windowed`** — 슬라이딩 윈도우. 크기 n짜리 창을 한 칸씩 밀면서 겹치는 부분 리스트를 만든다. 데이터가 연속된 시간의 값처럼 계열을 이룰 때 쓴다
- **`chunked`** — 주어진 크기로 겹치지 않게 자른다. 마지막 조각에는 남은 만큼만 담긴다
- **`zip`** — 두 컬렉션에서 같은 인덱스의 원소끼리 쌍을 만든다. 결과 길이는 짧은 쪽에 맞춘다
- **`flatMap`** — 원소마다 함수로 변환하고 그 결과를 하나의 리스트로 합친다
- **`flatten`** — 변환 없이 컬렉션의 컬렉션을 평평하게 편다

```kotlin
val temperatures = listOf(27.7, 29.8, 22.0, 35.5, 19.1)
println(temperatures.windowed(3))
// [[27.7, 29.8, 22.0], [29.8, 22.0, 35.5], [22.0, 35.5, 19.1]]
// ...
println(temperatures.chunked(2))
// [[27.7, 29.8], [22.0, 35.5], [19.1]]
```

온도 다섯 개에 크기 3짜리 창을 대면 창은 세 개다. 창이 한 칸씩 밀리니 가운데 `22.0`은 세 창에 다 들어간다. `chunked(2)`는 둘씩 끊고 남은 `19.1` 하나를 마지막 조각으로 둔다. 둘 다 람다를 받으면 조각마다 람다를 적용한 값만 남긴다. `windowed(3) { it.sum() / it.size }`는 창마다 평균을 내고 `chunked(2) { it.sum() }`는 조각별 합 `[57.5, 57.5, 19.1]`을 돌려준다.

`zip`도 람다를 받으면 쌍 대신 람다의 결과를 모은다. `peopleNames.zip(peopleAges) { name, age: Int -> Person(name, age) }`는 이름 목록과 나이 목록으로 `Person` 목록을 만든다. 중위 표기 `a zip b`로도 부르고 `zip`을 이어 부르면 리스트를 셋 이상 합친다.

```kotlin
val library =
    listOf(
        Book("Kotlin in Action", listOf("Isakova", "Elizarov", "Aigner", "Jemerov")),
        Book("Atomic Kotlin", listOf("Eckel", "Isakova")),
        Book("The Three-Body Problem", listOf("Liu")),
    )

val authors = library.flatMap { it.authors }
// [Isakova, Elizarov, Aigner, Jemerov, Eckel, Isakova, Liu]
println(authors.toSet())
// [Isakova, Elizarov, Aigner, Jemerov, Eckel, Liu]
```

책 세 권이 저자 이름 일곱 개가 된다. 원소마다 `authors` 리스트로 바꾸면 리스트 세 개가 나오는데, `flatMap`은 그걸 한 번 더 펴서 이름 리스트 하나로 만든다. 두 권에 이름을 올린 `Isakova`는 두 번 들어간다. **펴기만 하고 중복은 건드리지 않는다.** 중복을 지우려면 결과에 `toSet()`을 붙인다. 그러면 `Isakova`가 하나만 남은 여섯 명이 된다. 이미 리스트의 리스트가 있고 바꿀 게 없으면 `nestedList.flatten()`으로 충분하다.

## `ifEmpty`는 비었을 때만 기본값을 대고, 공백뿐인 문자열은 `ifBlank`가 잡는다

처리할 원소가 있을 때만 처리를 이어 가는 게 맞는 경우가 있다. 비어 있을 때 쓸 값을 람다로 미리 달아 둔다.

- **`ifEmpty`** — 비어 있으면 람다가 만든 기본값을, 아니면 자기 자신을 돌려준다. `empty.ifEmpty { listOf("no", "values", "here") }`는 `[no, values, here]`이고 원소가 있는 `full`은 `[a, b, c]` 그대로다
- **`ifBlank`** — 문자열에 쓴다. 비어 있거나 공백만 있으면 기본값을 돌려준다

```kotlin
val blank = " "
// ...
println(blank.ifEmpty { "empty" })
//
println(blank.ifBlank { "empty" })
// empty
```

공백 한 칸짜리 문자열은 비어 있지 않다. 그래서 `ifEmpty`는 기본값 대신 공백을 그대로 돌려주고 출력 주석이 비어 보이는 게 그 공백이다. **텍스트에서 "비었다"를 "공백만 있다"까지 넓히려면 `ifBlank`다.**

## 시퀀스는 원소를 하나씩 연산 끝까지 흘려 보내고, 최종 연산이 불려야 계산한다

컬렉션 연산을 이으면 단계마다 결과가 새 리스트에 담긴다. `map` 다음 `filter`면 `map`의 결과 리스트가 하나 생기고 `filter`가 그걸 다시 돈다. 시퀀스는 자바의 스트림처럼 중간 임시 컬렉션 없이 연산을 잇는다.

- **시퀀스(`Sequence`)** — 원소를 한 번에 하나씩 열거하는 인터페이스. 원소는 필요할 때 계산된다(지연 계산)
- **`asSequence()`** — 어떤 컬렉션이든 시퀀스로 바꾸는 확장 함수. 끝에서 `toList()`로 다시 리스트를 만든다
- **중간 연산** — `map`·`filter`처럼 다른 시퀀스를 돌려준다. 그 시퀀스는 원래 시퀀스의 원소를 어떻게 바꿀지 알고만 있다. 항상 지연 계산된다
- **최종 연산** — `toList()`·`sum()`처럼 결과를 돌려준다. 결과는 컬렉션이나 원소, 수 또는 다른 객체다. 이게 불려야 미뤄 둔 계산이 실행된다

```kotlin
people
    .asSequence()
    .map(Person::name)
    .filter { it.startsWith("D") }
    .toList()
```

즉시 계산이면 `map`이 모든 사람의 이름 리스트를 먼저 만들고 `filter`가 그 리스트를 다시 돈다. 시퀀스에서는 Dmitry가 `map`과 `filter`를 다 거친 다음에 John이 `map`으로 들어간다. **연산 단위가 아니라 원소 단위로 흐른다.** 그래서 어떤 원소는 아예 계산되지 않는다. `find` 같은 쇼트서킷 연산이 뒤에 붙으면 조건에 맞는 원소를 만나는 순간 끝나고 나머지 원소는 `map`도 거치지 않는다. 연산 순서도 비용을 바꾼다. 원소를 거르는 `filter`를 앞에 둘수록 뒤 연산이 처리할 원소가 줄어든다.

- **`generateSequence`** — 첫 원소와, 이전 원소를 받아 다음 원소를 계산하는 람다로 시퀀스를 만든다

```kotlin
val naturalNumbers = generateSequence(0) { it + 1 }
val numberTo100 = naturalNumbers.takeWhile { it <= 100 }
println(numberTo100)
// kotlin.sequences.TakeWhileSequence@4ff00844
println(numberTo100.sum()) // 결과를 계산할 때 모든 지연 계산이 수행된다
// 5050
```

`naturalNumbers`는 0부터 끝없이 이어지는 시퀀스인데 선언만으로는 아무것도 계산하지 않는다. `takeWhile`도 중간 연산이라 `numberTo100`을 찍으면 숫자가 아니라 `TakeWhileSequence` 객체가 나온다. 최종 연산 `sum()`을 부를 때 비로소 0부터 100까지 만들어 더하고 `5050`이 나온다. 끝이 없는 수열을 선언할 수 있는 것도 계산을 미루기 때문이다.

그렇다고 시퀀스가 기본은 아니다. 중간 컬렉션을 만들더라도 즉시 계산 컬렉션 연산이 더 효율적이고 시퀀스는 큰 컬렉션에 연산을 연쇄할 때 꺼낸다.
