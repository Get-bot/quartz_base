## 이 장에서 남은 것

- 람다는 **함수에 넘기는 코드 블록**이다. 메서드 하나짜리 익명 객체를 만들어 넘기던 자리를 중괄호 하나가 대신한다.
- 맨 뒤 인자가 람다면 **괄호 밖으로 뺀다.** 타입은 컴파일러가 모르겠다고 할 때만 적고, 파라미터가 하나면 이름 대신 `it`을 쓴다.
- 람다는 **`final`이 아닌 바깥 변수도 캡처해서 바꾼다.** 다만 바뀌는 건 람다가 실행될 때라서 클릭 핸들러 안의 `clicks++`는 함수가 돌려주는 값에 잡히지 않는다.
- 이미 있는 함수는 람다로 감싸지 않고 **`::`로 값으로 만든다.** 생성자, 확장 함수, 특정 인스턴스에 묶인 프로퍼티도 같은 문법이다.
- `with`·`apply`·`also`는 블록 안의 수신 객체를 정하고 **무엇을 돌려주느냐로 갈린다.** `with`는 람다의 결과를, `apply`와 `also`는 수신 객체를 돌려준다.

## 람다는 코드 블록을 값으로 넘기고, 호출 문법은 구분자를 걷어내는 쪽으로 줄어든다

자바에서 버튼 클릭을 처리하려면 `OnClickListener`를 구현한 익명 객체를 만들어 넘겼다. 객체를 만들긴 하지만 실제로 넘기고 싶은 건 `onClick` 안의 코드 몇 줄이다. 람다는 클래스 선언과 인스턴스 생성을 건너뛰고 그 코드 블록을 바로 함수에 넘긴다. **메서드가 하나뿐인 익명 객체 자리에 람다가 들어간다.**

```kotlin
button.setOnClickListener(object: OnClickListener {
    override fun onClick(p0: View) {
        println("CLICKED")
    }
})

//람다로 전환
button.setOnClickListener {
    println("CLICKED")
}
```

- **람다식(lambda expression)** — 다른 함수에 넘길 수 있는 작은 코드 조각. 항상 중괄호로 감싸고 화살표 `->` 앞이 파라미터 목록, 뒤가 본문이다. `{ x: Int, y: Int -> x + y }`
- **결괏값** — 본문이 여러 줄이면 맨 마지막 식의 값이 람다의 결과다
- **변수에 저장** — `val sum = { x: Int, y: Int -> x + y }`로 담아 두고 `sum(1, 2)`처럼 함수처럼 부른다. 이때는 타입을 추론할 문맥이 없어서 파라미터 타입을 꼭 적는다
- **`run`** — 인자로 받은 람다를 그 자리에서 실행하는 라이브러리 함수. 식이 와야 하는 자리에서 블록을 돌릴 때 쓴다. `val myFavoriteNumber = run { ... }`는 블록 안의 `println` 두 줄을 실행하고 마지막 식 `42`를 담는다. 부가 비용은 없다

효과는 컬렉션에서 크다. 나이가 가장 많은 사람을 찾는 `findTheOldest`는 최댓값과 그 사람을 담을 변수 둘에 `for` 루프까지 열 줄인데, 표준 라이브러리로는 `people.maxByOrNull { it.age }` 한 줄이다. 컬렉션 작업은 대부분 람다나 멤버 참조를 받는 라이브러리 함수 하나로 끝난다.

호출 문법은 같은 호출을 한 단계씩 줄여 가며 익힌다. 처음 모양은 구분자가 많아 읽기 어렵다.

```kotlin
people.maxByOrNull({ p: Person -> p.age })

// 람다를 괄호 밖으로 빼기
people.maxByOrNull() {p: Person -> p.age}

// 유일한 인자, 괄호 뒤 람다 괄호 제거
people.maxByOrNull { p: Person -> p.age }
```

줄이는 규칙은 넷이다.

- **괄호 밖으로** — 함수 호출의 맨 뒤 인자가 람다면 괄호 밖으로 뺀다. `joinToString(separator = " ") { p: Person -> p.name }`처럼 다른 인자는 괄호 안에 남는다
- **빈 괄호 지우기** — 람다가 유일한 인자면 괄호 뒤에 쓰고 빈 괄호를 지운다
- **타입 생략** — 파라미터 타입은 문맥에서 추론된다. `people`이 `Person` 목록이니 `p`가 `Person`인 걸 컴파일러가 안다. `{ p -> p.age }`
- **`it`** — 파라미터가 하나이고 타입을 추론할 수 있으면 이름도 지운다. 이름을 따로 붙이지 않았을 때만 `it`이라는 이름이 자동으로 생긴다. `{ it.age }`

람다가 둘 이상이면 하나만 밖으로 빼지 말고 전부 괄호 안에 두는 편이 읽기 쉽다. 타입은 처음부터 적지 않는다. **컴파일러가 타입을 모르겠다고 할 때만 적는다.**

## 람다는 바깥 변수를 캡처하고 `var`도 바꾸지만, 바뀌는 시점은 람다가 실행될 때다

함수 안에서 정의한 람다는 그 함수의 파라미터와 로컬 변수를 전부 본다. `printMessageWithPrefix`의 `forEach` 람다는 자기 파라미터가 아닌 바깥의 `prefix`를 그대로 쓴다. 자바 람다는 값이 바뀌지 않는(사실상 `final`인) 변수만 쓰지만 코틀린 람다는 `final`이 아닌 변수도 읽고 바꾼다. `printProblemCounts`는 `var clientErrors`와 `var serverErrors`를 `forEach` 안에서 `++`로 센다.

- **캡처한 변수(captured variable)** — 람다가 접근하는 바깥 변수. 람다를 저장해 두고 함수가 끝난 뒤에 실행해도 본문은 그 변수를 여전히 읽고 쓴다
- **`final` 변수를 캡처하면** — 람다 코드를 변수 값과 함께 저장한다
- **`final`이 아닌 변수를 캡처하면** — 변수를 특별한 래퍼로 감싸고 그 래퍼에 대한 참조를 람다 코드와 함께 저장한다. 래퍼를 거치니 나중에도 값을 바꾸고 읽는다

함정은 실행 시점이다. 람다를 이벤트 핸들러처럼 나중에 비동기로 실행되는 자리에 넘기면 로컬 변수는 람다가 실행될 때 바뀐다.

```kotlin
fun tryToCountButtonClick(button: Button): Int {
    var clicks = 0
    button.onClick { clicks++ }
    return clicks
}
```

이 함수는 항상 0을 돌려준다. 핸들러는 클릭이 일어날 때 실행되는데 함수는 그보다 먼저 `clicks`를 반환하고 끝난다. `clicks++`는 그 뒤 클릭마다 값을 올리지만 이미 반환된 값과는 상관이 없다. 클릭 수를 제대로 세려면 카운터를 함수 안이 아니라 클래스 프로퍼티처럼 함수 밖에 두고 나중에 그 값을 본다. **캡처는 변수를 살려 둘 뿐 결과를 기다려 주지 않는다.**

## 이름이 있는 함수는 람다로 감싸지 않고 `::`로 넘긴다

`people.maxByOrNull { person: Person -> person.age }`는 `age`를 읽기만 하는 람다다. 넘기려는 코드가 이미 함수나 프로퍼티로 있으면 람다로 한 번 더 감쌀 이유가 없다. `people.maxByOrNull(Person::age)`가 같은 일을 한다.

- **멤버 참조(member reference)** — `클래스::멤버`. 이중 콜론 `::`이 함수를 값으로 바꾼다. 정확히 한 메서드를 호출하거나 한 프로퍼티에 접근하는 함수 값이고 그 멤버를 호출하는 람다와 타입이 같다
- **최상위 함수 참조** — 클래스 없이 `::salute`. `run(::salute)`처럼 넘긴다
- **위임만 하는 람다** — `{ person: Person, message: String -> sendEmail(person, message) }`처럼 받은 인자를 그대로 다른 함수에 넘기는 람다는 `::sendEmail` 하나로 바꾼다
- **생성자 참조** — `::Person`. 인스턴스를 만드는 동작을 값으로 저장해 두고 나중에 `createPerson("Dmitry", 42)`처럼 부른다. 생성을 미루거나 저장할 때 쓴다
- **확장 함수 참조** — `fun Person.isAdult()`도 `Person::isAdult`로 멤버와 똑같이 참조한다
- **값과 엮인 호출 가능 참조(bound callable reference)** — 클래스 대신 인스턴스 앞에 `::`을 붙인다. 특정 객체의 메서드 호출이나 프로퍼티 접근을 가리킨다

멤버 참조와 값과 엮인 참조의 차이는 호출할 때 드러난다.

```kotlin
val seb = Person("Dmitry", 42)
val personAgeFunction = Person::age // Person이 주어지면 나이를 돌려주는 참조
// ...
val sebsAgeFunction = seb::age // 특정 Person의 나이를 돌려주는, 값과 엮인 호출 가능 참조
```

`Person::age`는 누구의 나이를 읽을지 모르니 `personAgeFunction(seb)`처럼 `Person`을 받아야 한다. `seb::age`는 이미 `seb`에 묶여 있어서 `sebsAgeFunction()`처럼 인자 없이 부른다. 같은 `::` 문법이고 **참조가 수신 객체를 들고 있느냐**만 다르다.

## 추상 메서드가 하나뿐인 인터페이스 자리에는 람다를 넘기고, 객체로 바꾸는 일은 컴파일러가 한다

코틀린 람다는 자바 API와 그대로 맞물린다. 자바 라이브러리는 `Runnable`, `OnClickListener`처럼 메서드 하나짜리 인터페이스를 인자로 받는데 그 자리에 람다를 넘기면 된다.

- **함수형 인터페이스(functional interface)** — 추상 메서드가 단 하나뿐인 인터페이스. 단일 추상 메서드(single abstract method)를 줄여 SAM 인터페이스라고도 한다. 람다의 파라미터가 그 유일한 추상 메서드의 파라미터에 대응한다
- **SAM 변환** — 함수형 인터페이스를 받는 자리에 람다를 넘기면 컴파일러가 그 인터페이스를 구현한 익명 클래스의 인스턴스로 바꾼다
- **SAM 생성자** — 컴파일러가 만들어 주는 함수. 람다를 함수형 인터페이스의 인스턴스로 명시적으로 바꾼다. 이름은 인터페이스 이름과 같고 인자로 람다 하나를 받는다. `Runnable { print("All done!") }`

익명 객체를 손으로 만들 때와 달리 인스턴스를 몇 개 만들지는 컴파일러가 정한다.

- **바깥 변수를 캡처하지 않는 람다** — 익명 객체 하나를 만들어 두고 호출마다 재사용한다
- **캡처하는 람다** — 호출마다 새 인스턴스를 만들고 캡처한 변수를 그 안에 저장한다. 호출마다 담을 값이 다르니 같은 인스턴스를 쓸 수 없다
- **`inline` 함수에 넘긴 람다** — 익명 클래스 자체가 생기지 않는다. `filter`·`map` 같은 코틀린 컬렉션 함수가 이쪽이라 인스턴스가 새로 만들어져 메모리를 낭비할 걱정이 없다

SAM 생성자는 자동 변환이 안 되는 자리에서 꺼낸다. 함수형 인터페이스 인스턴스를 반환하는 함수는 람다를 그대로 반환하지 못하니 `return Runnable { print("All done!") }`처럼 감싼다. 람다로 만든 리스너를 변수에 담아 여러 곳에 쓸 때도 그렇다. `val listener = OnClickListener { view -> ... }`로 만들어 `view.id`로 어느 버튼인지 가르고 `button1`과 `button2`에 같은 리스너를 등록한다.

익명 객체와 다른 점이 하나 더 있다. **람다에는 자기 자신을 가리키는 `this`가 없다.** 컴파일러에게 람다는 객체가 아니라 코드 블록이라서 람다를 변환한 익명 클래스의 인스턴스를 참조할 방법이 없다. 람다 안의 `this`는 람다를 둘러싼 클래스의 인스턴스다. 리스너가 이벤트를 처리하다가 자기 등록을 해제해야 하면 람다 대신 익명 객체로 구현한다.

코틀린에서 이런 인터페이스를 직접 선언할 때는 `fun interface`를 쓴다.

- **`fun interface`** — 함수형 인터페이스를 선언한다. 추상 메서드는 하나뿐이지만 비추상 메서드는 여럿 가져도 된다
- **넘기는 쪽** — 이 타입을 파라미터로 받는 함수에는 람다를 바로 넘기거나 시그니처가 맞는 함수 타입 값을 넘긴다

```kotlin
fun interface IntCondition {
    fun check(i: Int): Boolean // 추상 메서드

    fun checkString(s: String) = check(s.toInt()) // 비추상 메서드

    fun checkChar(c: Char) = check(c.digitToInt())
}
// ...
checkCondition(1) { it % 2 != 0 } // 람다 직접 사용
```

`IntCondition`의 추상 메서드는 `check` 하나라서 람다 `{ it % 2 != 0 }`가 곧 `check`의 구현이다. `checkString`과 `checkChar`는 입력을 `Int`로 바꿔 그 `check`를 부르는 비추상 메서드라 람다가 구현할 몫이 아니다. `checkCondition(i: Int, condition: IntCondition)`의 두 번째 자리에는 `(Int) -> Boolean` 타입 변수를 넘겨도 된다.

## `with`·`apply`·`also`는 블록 안의 수신 객체를 정하고, 무엇을 돌려주느냐로 갈린다

- **수신 객체 지정 람다(lambda with receiver)** — 본문 안에서 수신 객체를 명시하지 않고 그 객체의 메서드를 부르는 람다. 본문이 둘러싼 코드와 다른 문맥에서 돌아서 코드를 구조화할 때 쓴다

표준 라이브러리 함수 셋이 이 람다를 받는다.

- **`with`** — 첫 번째 인자로 받은 객체를 두 번째 인자인 람다의 수신 객체로 만든다. 람다 안에서 그 객체는 `this`이고 `this`도 생략할 수 있다. 람다의 결과를 돌려준다
- **`apply`** — 아무 타입에나 확장 함수로 호출한다. 호출한 객체가 람다의 수신 객체가 되고 항상 그 객체를 돌려준다
- **`also`** — `apply`처럼 수신 객체에 어떤 동작을 하고 수신 객체를 돌려준다. 다만 람다 안에서 그 객체를 수신 객체가 아니라 인자로 받아서 이름을 붙이거나 `it`으로 부른다

셋을 가르는 축은 둘이다. **람다 안에서 객체가 `this`냐 `it`이냐, 돌려주는 게 람다의 결과냐 수신 객체냐.** `with`는 `this`와 람다 결과, `apply`는 `this`와 수신 객체, `also`는 `it`과 수신 객체다.

`with`는 같은 객체 이름을 반복하던 코드를 줄인다. 알파벳을 찍는 `alphabet`은 `result.append`를 거듭 쓰는데, `with(StringBuilder())`로 감싸면 `append`만 남고 변수 선언도 사라진다.

```kotlin
fun alphabet(): String{
    val result = StringBuilder()
    for (letter in 'A'..'Z') {
        result.append(letter)
    }
    result.append("\nNow I know the alphabet!")
    return result.toString()
}

// 명시적 변수 제거
fun alphabetWith() =
    with(StringBuilder()) {
        for (letter in 'A'..'Z') {
            append(letter) // stringBuilder가 this가 됨
        }
        append("\nNow I know the alphabet!")
        toString()
    }
```

사이 단계에서는 `val stringBuilder`를 따로 두고 람다 안에서 `this.append(letter)`로 썼다. `this`를 지우고 수신 객체를 `with`의 인자 자리에서 바로 만들면 위 블록의 두 번째 모양이 된다. 마지막 식 `toString()`의 결과가 `with`의 반환값이다.

`apply`는 수신 객체를 돌려주니 객체를 만들면서 바로 초기화하는 자리에 맞는다. 같은 알파벳 함수를 `StringBuilder().apply { ... }.toString()`으로 쓰면 `apply`가 `StringBuilder`를 돌려주니 문자열은 밖에서 `toString()`으로 꺼낸다. 인스턴스를 만들면서 프로퍼티 몇 개를 바로 채우는 경우가 대표적이다.

```kotlin
fun createViewWithCustomAttributes(context: Context) =
    TextView(context).apply {
        text = "Sample text"
        textSize = 20f
        setPadding(10, 0, 10, 0)
    }
```

`TextView`를 만들고 `apply` 안에서 `text`, `textSize`, `setPadding`을 수신 객체 없이 부른 뒤 그 `TextView`가 그대로 함수의 결과가 된다. `apply`는 확장 함수라서 `TextView`를 정의한 라이브러리가 따로 지원하지 않아도 이렇게 쓴다. **어떤 객체든 빌더 스타일로 만들고 초기화한다.**

`also`는 체인 중간에서 객체를 받아 곁가지 작업을 하고 그대로 넘긴다.

```kotlin
val reversedLongFruits =
    fruits
        .map { it.uppercase() }
        .also { upperCaseFruits.addAll(it) }
        .filter { it.length > 5 }
        .also(::println)
        .reversed()
```

`map`이 만든 대문자 리스트를 첫 `also`가 `it`으로 받아 `upperCaseFruits`에 담고 리스트는 그대로 `filter`로 넘어간다. 두 번째 `also`는 람다 대신 `::println` 참조를 받아 중간 결과를 찍는다. 두 동작 모두 원래 수신 객체를 인자로 받는 동작이다. `also`가 맞는 자리가 이런 곳이다.
