# 원문(raw) 형식 — 절 지도 + 절별 메모

위치 `content/private/<book>-chNN-raw.md`. `private/`는 빌드와 git 둘 다에서 빠지므로 책 문장이 그대로 있어도 된다. 원문은 **정리본을 쓸 때의 유일한 입력**이고, 나중의 내가 "그때 뭘 봤지"를 되짚는 보관소다. 그래서 메모는 다시 읽히게 문장으로 정리하되 **내용은 더하지도 빼지도 않는다.** 코드는 사용자가 친 그대로 두고 오타만 고친다. 처음 받은 메모는 `_workspace/book-digest/<book>-chNN/raw.original.md`에 그대로 백업한다.

### 절 지도 표기

| 표기 | 뜻 | 정리본에서 |
|---|---|---|
| `- [x] N.n 제목` | 읽고 메모가 있다 | 주장 절의 재료 |
| `- [ ] N.n 제목 — 이유` | 건너뛰었다 | '넘어간 것'에 들어간다 |
| `- [~] N.n 제목 — 이유` | 훑기만 했다 | '넘어간 것'에 들어간다 |

이유는 사용자의 말로만 적는다. raw나 기존 정리본에 이유가 없으면 `—` 뒤를 비워 두고 보고에서 묻는다. verify는 `[ ]`·`[~]` 항목의 절 번호가 정리본 '넘어간 것'에 전부 있는지 대조한다.

**지도는 `N.n` 한 단계로 유지한다.** `1.3.1`, `1.3.2` 같은 하위 절까지 쪼개면 건너뛴 항목이 열 개 단위로 늘어나고, '넘어간 것'이 그걸 전부 거울처럼 받아야 해서 둘이 어긋난다(실측: 20항 지도를 만든 런에서 하위 절 3개가 '넘어간 것'에서 누락돼 verify FAIL). 하위 절은 부모 절로 올려 한 줄로 적고, 사용자의 메모가 직접 하위 번호를 쓸 때만 그 단계를 쓴다. 지도의 목적은 목차 재현이 아니라 "내가 어디를 안 봤는지"를 한눈에 남기는 것이다.

절 지도가 raw에 없을 때: 책은 사용자만 볼 수 있다. 아는 판본의 목차를 **초안으로 제안하고 확인을 받은 뒤** 채운다. 판본이 다르면 절 번호와 제목이 갈린다(예: Kotlin in Action 1판과 2판은 장 수부터 다르다). 확인 없이 확정하지 않는다.

### 다른 절은 만들지 않는다

원문에 있는 것은 **절 지도 + 절별 메모와 코드**(+ 첫 절 앞에서 적은 메모의 `## 도입`, 배치를 못 한 메모의 `## 절 미상`)뿐이다. '걸린 것 / 질문'·'다음 장으로 미룬 것' 같은 절은 만들지 않는다. 채울 말이 raw에 없으면 빈 불릿만 남고, 채우려면 사용자가 하지 않은 말을 지어내게 된다.

책 문장에 따로 표기를 붙이지도 않는다. 원문은 `private/`라 공개되지 않고, 정리본으로 새는지는 verify의 전사 비율이 본다.

## 정리의 한계선

정리 전 메모는 Phase 1을 시작할 때 `_workspace/book-digest/<book>-chNN/raw.original.md`로 백업한다. 이미 있으면 덮어쓰지 않는다 — 처음 받은 메모가 원본이다. 한계선을 넘었는지는 이 원본과 나란히 놓고 본다. 이미 `status: digested`인 raw는 정리가 끝난 것이라 다시 정리하지 않는다.

### 메모

하는 것:

- 메모를 해당 절 아래로 옮기기. 첫 절 앞에서 적은 메모는 `## 도입`으로
- 오탈자 교정 — `표용`→`포용`, `엘비스 연사자`→`엘비스 연산자`, `equlas`→`equals`, `overried`→`override`, `pulbic`→`public`. 용어·API 이름이 틀리면 나중의 내가 잘못 알게 되니 빠짐없이 고친다
- 띄어쓰기·맞춤법 — `가질수`→`가질 수`, `가싱성`→`가시성`, `짦은`→`짧은`
- 식별자를 백틱으로 — `override`, `open`, `public`, `StringBuilder`처럼 코드에 쓰는 이름
- 완결된 해라체 문장으로 — 명사형으로 끊긴 메모(`~ 가능`, `~ 필수`, `~ 사용`)는 `~할 수 있다`, `~해야 한다`로 끝맺고, 이어 붙은 두 생각은 마침표로 끊는다. 끊어도 같은 불릿 안에 둔다. 이미 완결된 문장은 건드리지 않는다
- 불릿 표기 맞추기 — 불릿 없이 줄로 적은 메모는 `- ` 불릿으로. 하위 불릿은 들여쓰기 그대로
- 마크다운 형식 — 제목·코드블록 앞뒤 빈 줄, 줄 끝 공백 제거
- 절 지도 만들기 (내용은 raw에 있는 것만)

하지 않는 것:

- 요약하기, 메모 두 개를 하나로 합치기, 메모 지우기 — 겹쳐 보여도 둘 다 둔다
- raw에 없는 설명·예시·근거 보태기. 문장을 끝맺는 데 필요한 조사·어미까지만 쓴다
- 뜻 바꾸기 — `거의 모든 경우`를 `모든 경우`로, `보통`을 `항상`으로 바꾸는 식의 강도 조정
- 사용자가 쓴 기호(`→`, `—`, `X`)와 `*강조*`, 들여쓰기 구조 바꾸기
- 표와 `###` 소제목을 불릿으로 바꾸기 — 형식은 그대로 두고 안의 오탈자·띄어쓰기만 고친다
- 어느 절인지 확신이 없는 메모를 추측으로 배치하기 — `## 절 미상`으로
- humanize-korean에 넘기기. 윤문은 메모를 글로 만든다

**메모 한 줄(불릿이면 불릿 하나)은 정리 뒤에도 불릿 하나다.** 원본의 메모 줄 수보다 불릿이 줄었으면 합친 것이고, 늘었으면 없던 말을 보탠 것이다. 정리한 메모 수와 고친 오탈자는 보고에 남긴다.

전/후 (ch04.md 메모):

```text
- 상위 클래스나 상위 인터페이스에 있는 프로퍼티나 메서드를 오버라이드할 때 overried변경자 사용 자바와 달리 overried 변경자 사용 필수
- 클래스는 오직 하나만 확장 가능
- 코틀린은 pulbic 함수 안에서 그보다 가시성이 더 낮은 타입을 참조하지 못하게 한다.
```

```text
- 상위 클래스나 상위 인터페이스에 있는 프로퍼티나 메서드를 오버라이드할 때 `override` 변경자를 쓴다. 자바와 달리 `override` 변경자는 필수다.
- 클래스는 오직 하나만 확장할 수 있다.
- 코틀린은 `public` 함수 안에서 그보다 가시성이 더 낮은 타입을 참조하지 못하게 한다.
```

첫 줄은 오타를 고치고 이어 붙은 두 생각을 끊었다. 둘째 줄은 명사형을 끝맺었다. 셋째 줄은 이미 문장이라 오타와 백틱만 고쳤다. 세 줄 모두 불릿 수와 뜻이 그대로다.

### 코드

코드는 사용자가 책을 따라 친 기록이다. 정리본의 코드는 여기서만 발췌하고, verify가 줄 단위로 출처를 대조한다. 그래서 **오타까지만 고친다.** 오타를 남기면 정리본에 틀린 코드가 그대로 공개되고, 오타 말고 더 손대면 친 기록이 아니게 된다.

하는 것:

- 줄 끝 공백 제거 — IDE에서 붙여넣으면 줄 끝에 공백 두 칸이 붙는다(실측: ch04.md)
- 깨진 코드블록 경계 복구 — 닫는 펜스가 없거나 메모가 코드블록 안으로 들어간 경우
- 언어 태그가 없는 코드블록에 태그 붙이기(`kotlin`)
- 붙여넣기 오류 수정 — 줄이 합쳐져 코드가 깨진 경우만. `// I'm focusable!}`는 `// I'm focusable!`과 다음 줄 `}`로 나눈다(ch04.md)
- 오타 수정 — 식별자·키워드·API 이름을 잘못 쳐서 컴파일이 안 되는 것. `int`→`Int`, `sefOf`→`setOf`, `readline`→`readLine`, `Color.Red`→`Color.RED`, 문자열 템플릿 `$(color.b)`→`${color.b}`(실측: ch02·ch03). 주석 안 오타(`몰록`→`목록`)도 고친다

고친 코드는 전부 보고에 전/후로 남긴다.

하지 않는 것:

- 이름 바꾸기, 포맷·들여쓰기 고치기, 출력 주석 보태기
- 로직·구조 고치기 — 오타가 아니라 코드가 하는 일이 틀려 보이면(반환 타입이 맞지 않는다, 분기가 빠졌다) 고치지 말고 보고에서 묻는다. 오타인지 로직인지 헷갈려도 묻는다
- 일부러 틀린 코드 고치기 — `// 오류:` 주석이 붙은 예제는 컴파일 오류를 보여주려고 친 것이다(ch04.md 가시성 예제)
- 코드블록 합치기·나누기·지우기

verify는 원본 백업이 있으면 raw 코드블록이 원본과 같은지 대조한다(줄 끝 공백·언어 태그 무시). 다르면 WARN이 뜨고, 보고한 오타·붙여넣기 오류 수정과 맞아야 한다.
