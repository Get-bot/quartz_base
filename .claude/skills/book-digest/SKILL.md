# book-digest — 원문에서 정리본까지

책 정리가 두 벌로 나뉜다는 것이 이 스킬의 전제다.

- **원문(raw)** `content/private/<book>-chNN-raw.md` — 책을 보면서 적은 메모를 절 지도 아래 문장으로 정리한 것. 코드는 사용자가 친 그대로이고 오타만 고친다. 책 문장이 그대로 있어도 된다. `private/`는 빌드(quartz.config.yaml ignorePatterns)와 git(.gitignore) 둘 다에서 빠진다. 정리하기 전 메모는 `_workspace/book-digest/<book>-chNN/raw.original.md`에 남는다.
- **정리본(digest)** `content/study/<book>/chNN.md` — 원문을 덮고 나서 내 말로 다시 쓴 것. 공개된다. 이게 지식베이스다.

정리본을 책의 절 순서로 쓰면 전사가 되고, 전사는 다시 찾아 읽을 이유가 없다(이 레포의 기존 `study/` 노트 15편에 걸린 링크가 0개였다). 그래서 정리본의 소제목은 **책의 절이 아니라 이 장이 하는 주장**이고, 그 아래 본문에는 **그 장이 가르친 개념**이 들어간다. 주장만 있으면 나중에 찾아볼 것이 없다. 개념 정의는 책 문장을 그대로 옮겨도 된다 — 그게 제일 정확할 때가 있다. 영역 폴더로 빼는 노트는 사용자의 코드·경험이 붙을 때만 만든다 — 언어 책은 그런 장이 드물어서, 다 빼면 관리가 안 되고 안 빼면 내용이 private에 갇힌다. 정리본이 그 사이를 맡는다.

## 시작하기 전에 읽을 것

스킬이 로드될 때 표시되는 "Base directory for this skill" 경로가 `<skill-dir>` 이다.

| 파일 | 언제 | 왜 |
|---|---|---|
| `<skill-dir>/references/raw-format.md` | Phase 1 전 | 원문 형식. 절 지도 표기, 정리의 한계선(메모·코드) |
| `content/templates/book.md` | **Phase 2 전 (정본)** | 정리본의 절 구성. 뼈대는 이 파일이 정본이고, 사용자가 고쳤으면 그쪽을 따른다 |
| `<skill-dir>/references/digest-format.md` | Phase 2 전 | 각 절을 왜·어떻게 쓰는지. 보충의 범위, 책 index 뼈대 |
| `<skill-dir>/references/voice.md` | Phase 2 전 | 사용자의 문체. humanize 전에 1차로 맞춘다 |
| `<skill-dir>/references/humanize-handoff.md` | Phase 4 전 | humanize-korean에 넘기고 받는 절차, 롤백 |
| `content/notes/writing-guide.md` | Phase 0 | 레포의 규칙. 이 스킬과 다르면 레포가 우선 |

## 입력

- **책 slug** — `content/study/` 아래 폴더명. 새 책이면 영문 소문자+하이픈으로 사용자와 정한다.
- **장 번호 N** — 폴더는 `chNN`(두 자리), 표 행과 title은 `N`.
- **raw** — 파일 경로, 붙여넣은 텍스트, 또는 `content/study/<book>/chNN.md`에 템플릿을 깔고 위에 적은 메모(Phase 0이 가른다). 어느 쪽이든 Phase 1이 `content/private/<book>-chNN-raw.md`로 정리해 저장한다.
- **레포 루트** — `content/`와 `quartz.config.yaml`이 있는 곳. cwd가 아니면 사용자가 준 경로. 이후 모든 경로는 루트 기준.

## Phase 0 — 확인·백업 (정리본·raw는 아직 쓰지 않는다)

1. 루트·slug·N을 확정한다. `content/study/<book>/`과 `chNN.md`가 있는지 본다.
2. **`chNN.md`가 있으면 정리본인지 raw인지 먼저 가른다.** 사용자는 템플릿을 깔고 그 위에 메모를 적기도 한다(실측: ch04.md). HTML 주석 밖에 `## 4.1`처럼 절 번호로 시작하는 H2가 있거나, 템플릿 안내문(`책을 덮고 나서도 기억나는 것 3~5줄`, `## 주장 하나를 문장으로` 등 — `scripts/verify_digest.py`의 `TEMPLATE_PHRASES`)이 남아 있으면 **raw다.**
   - raw면 3의 손글씨 보존을 적용하지 않는다. 파일 그대로를 `_workspace/book-digest/<book>-chNN/raw.original.md`로 백업하고 Phase 1의 입력으로 쓴다. 템플릿 잔재(안내문, 빈 불릿 `-`, `**개념 이름**` 예시, '넘어간 것'·'여기서 나온 노트'의 예시 항목 `4.4 ○○○`·`[[노트-파일명|…]]`, 원문 뼈대 주석)는 사용자의 메모가 아니니 버린다. 사용자가 템플릿 절에 직접 채운 것('이 장에서 남은 것' 불릿, '넘어간 것' 이유)은 손글씨라 Phase 2에 그대로 가져간다. `chNN.md`는 Phase 2가 정리본으로 덮어쓴다.
3. **raw가 아닌 기존 정리본은 사용자의 손글씨다.** `_workspace/book-digest/<book>-chNN/index.before-digest.md`로 먼저 백업한다. 그 안의 '이 장에서 남은 것'과 '넘어간 것'의 이유는 사용자가 책을 덮고 쓴 기억이라 raw에서 다시 만들지 않고 그대로 가져간다. 주장 절만 새로 채운다.
4. `.gitignore`에 `_workspace/`가 있는지 확인한다. humanize-korean이 cwd에 `_workspace/`를 만들고, 원본 백업도 여기 둔다. 없으면 한 줄 추가하고 보고에 적는다.
5. 관련 노트 후보를 미리 찾는다. raw의 핵심어(언어명, 개념어, 라이브러리명)로 `content/`를 Grep해 파일 목록을 잡아둔다. Phase 3의 영역 노트 후보를 고르고, 이미 있는 노트를 중복해 만들지 않기 위한 재료다. 정리본에 링크를 뿌리려고 찾는 게 아니다.

## Phase 1 — 원문 정리 → `references/raw-format.md`

- **정리 전에 원본을 백업한다.** 받은 메모(파일·붙여넣기·`study/chNN.md`) 그대로를 `_workspace/book-digest/<book>-chNN/raw.original.md`에 쓴다. 이미 있으면 덮어쓰지 않는다 — 처음 받은 메모가 원본이다.
- **메모는 문장까지 정리한다.** 메모를 절 아래로 모으고, 오탈자·띄어쓰기를 고치고, 식별자를 백틱으로 감싸고, 이어 붙은 메모를 끊어 완결된 해라체 문장으로 만든다. 메모 불릿 하나는 정리 뒤에도 불릿 하나다. 요약·합치기·지우기·없던 정보 추가는 하지 않는다 — 내용은 사용자의 것이고 바뀌는 건 읽히는 모양뿐이다. 한계선은 `raw-format.md`.
- **코드는 오타까지만 고친다.** 줄 끝 공백 제거, 깨진 코드블록 경계 복구, 빠진 언어 태그(`kotlin`) 붙이기, 붙여넣기 오류 수정, 그리고 **오타 수정** — 식별자·키워드·API 이름을 잘못 쳐서 컴파일이 안 되는 것(`int`→`Int`, `sefOf`→`setOf`, `readline`→`readLine`, `$(x)`→`${x}`)과 주석 안 오타. 정리본이 이 코드를 발췌하니 틀린 채로 두면 틀린 코드가 공개된다. 로직·구조는 고치지 않는다 — 오타가 아니라 하는 일이 틀려 보이면 보고에서 묻는다. `// 오류:` 주석이 붙은 예제처럼 일부러 틀린 코드는 그대로 둔다. 고친 코드는 전부 보고에 전/후로 남긴다. Phase 5가 원본 백업과 코드블록을 대조한다.
- 이미 `status: digested`인 raw를 다시 돌릴 때는 문장 정리를 다시 하지 않는다. 정리가 끝난 raw다. 절 지도 갱신처럼 요청받은 것만 고친다.
- 절 지도는 raw에 있으면 그대로 쓴다. 없으면 절 목록이 필요하다 — 아는 판본의 목차를 초안으로 제안하고 사용자에게 확인받는다. 책은 사용자만 볼 수 있다. 확인 없이 절 번호를 확정하지 않는다.
- 어느 절인지 모르는 메모는 `## 절 미상` 아래에 둔다. 추측으로 배치하지 않는다.
- 건너뛴 절의 이유는 raw나 기존 정리본에 있는 말만 쓴다. 없으면 `—` 뒤를 비우고 Phase 6에서 묻는다.
- 끝나면 frontmatter를 `status: digested`, `digest: study/<book>/chNN`로 맞춘다. 고친 오탈자, 문장으로 정리한 메모 수, 고친 코드는 보고에 목록으로 남긴다.

## Phase 2 — 정리본 → `references/digest-format.md` + `references/voice.md`

순서가 중요하다.

0. `content/templates/book.md`를 읽는다. 절 구성은 그 파일이 정본이다. 사용자가 절을 넣거나 뺐으면 그대로 따른다.
1. raw를 끝까지 읽는다.
2. raw를 닫고, "이 장이 하는 주장"을 3~6개 문장으로 적는다. 이게 H2 소제목이 된다.
3. 주장마다 2~4문단을 내 말로 쓴다. 그 주장이 딛고 선 개념부터 — 책이 "N가지"로 든 것은 N개를 다 적고 각각이 무슨 말인지 한 줄씩 붙인다(열거는 불릿, 판단은 문단). 그다음 왜 그런지, 무엇과 대비되는지.
4. 마지막에 raw와 대조해 빠진 근거와 틀린 사실만 보정한다.

raw를 보면서 쓰면 문장을 옮기게 된다. 주장을 먼저 세우면 책의 절 순서에서 풀린다.

- **'이 장에서 남은 것'은 사용자의 기억이다.** 기존 정리본에 있으면 그대로 둔다. 없으면 raw에서 반복·강조된 것으로 3~5줄 초안을 쓰고, 보고에서 "이건 내가 고른 것"이라고 밝힌다.
- 책 문장을 그대로 옮겨도 된다. 대신 소제목(주장)과 '이 장에서 남은 것'은 반드시 내 말로 쓴다. 이 둘까지 책 문장이면 정리본이 아니라 전사다.
- **보충은 이만큼 한다.** raw는 책을 보면서 급히 적은 것이라 이름만 있고 설명이 없는 자리가 있다. 그 자리는 채운다 — 개념 이름만 적혀 있으면 그게 무슨 말인지 한 줄, 목록에서 빠진 항목이 있으면 그 장이 든 만큼, raw의 용어·사실이 틀렸으면 고친다. 채우는 범위는 **그 장이 가르친 것**까지다.
- **raw 밖으로 나가지 않는다.** 그 장이 다루지 않은 주제로 넓히거나, 지어낸 경험·코드를 넣거나, 이 장과 직접 관계없는 노트로 링크를 뻗는 것은 보충이 아니라 다른 글이다. 정리본은 이 장의 정리다.
- **보충한 것은 보고한다.** raw에 없던 문장과 고친 내용을 Phase 6에 목록으로 남긴다. 나중에 "이건 책 말인가 내 말인가"를 되짚을 수 있어야 한다.
- **코드는 raw 코드블록에서만 가져온다.** raw에 있는 코드는 사용자가 친 것이다 — 책 예제를 따라 친 것도 포함된다. 넣는 자리는 글이 코드의 모양·단계·출력을 설명하는 곳뿐이다: 선언 여러 개를 머릿속에 세워야 따라오는 예제, 한 함수가 몇 단계로 바뀌는 과정, 출력이 직관과 다른 호출. 한 줄로 끝나는 문법은 인라인 코드로 충분하다. 블록당 15줄 안팎으로 필요한 줄만 발췌한다. 블록 수에는 상한을 두지 않는다 — 넣을지는 글이 그 코드를 설명하는지로만 정한다. raw에 없는 줄·출력 주석은 넣지 않고, 뺀 부분은 `// ...` 한 줄로 표시한다. Phase 5가 정리본 코드의 줄이 전부 raw 코드블록에 있는지 본다.
- 지어낸 "실제로 겪은 것"은 금지다. 사용자 프로젝트와의 접점은 Phase 0 검색에서 실제로 나온 노트가 있을 때만 언급한다.
- 길이 상한은 없다. Phase 5가 재는 전사 비율은 보고용이다 — 높다고 다시 쓰지 않고, 수치만 보고에 싣는다.
- '넘어간 것'에는 절 지도의 `[ ]`·`[~]` 항목이 전부 들어간다. `- N.3 제목 — 이유`. **건너뛴 절이 없으면 절 자체를 만들지 않는다.** "건너뛴 절은 없다" 한 줄도 남기지 않는다.
- frontmatter: `title: "N. 장 제목"`, `date` 오늘, `tags` [언어, book, <book>] 전부 kebab-case, `description` 장을 관통하는 한 문장, `draft: true`. draft 해제는 사용자가 한다.

## Phase 3 — 빼낸 노트와 책 index

- **영역 노트 후보**: 주장 중 사용자의 코드·경험(기존 TIL·노트)이 붙는 것만 후보로 **제안**한다. 만들지 않는다. 제안 한 줄의 형식은 `제목(문장) / 영역 폴더 / 왜 책 없이 혼자 살아남는가`. 사용자가 고르면 `content/templates/note.md`로 영역 폴더에 만들고, 영역 `index.md`의 큐레이션 한 줄은 초안을 보여주고 승인받은 뒤 넣는다.
- **'여기서 나온 노트'**: 위에서 노트를 **실제로 만들었을 때만** 이 절을 만들고 링크한다. 안 만들었으면 절 자체가 없다. "없다" 한 줄이나 빈 절을 남기지 않는다.
- **책 index** `content/study/<book>/index.md`: '읽은 장' 표에 행을 추가한다. 표 안의 파이프는 `\|`로 이스케이프한다.
  `| N | [[<book>/chNN\|장 제목]] | 남은 것 한 구절 |`
  책 폴더가 처음이면 `digest-format.md`의 책 index 뼈대로 만든다. 그 페이지는 사이트 안내라 합니다체다.
- 첫 장이면 `content/study/index.md`에 책 불릿을 추가할 문장 초안을 보고에 넣는다. 홈·MOC에 이미 책 이름이 있으면 건드리지 않는다.

## Phase 4 — 윤문 → `references/humanize-handoff.md`

정리본 본문 중 **주장 절만** humanize-korean에 넘긴다. frontmatter, '이 장에서 남은 것', '여기서 나온 노트', '넘어간 것', 코드블록은 `scripts/humanize_io.py`가 빼놓고 다시 붙인다. '남은 것'은 사용자의 기억이라 윤문하지 않는다 — 넘겼더니 쉼표와 어미가 바뀌었다(실측). 강도는 보수, 장르는 블로그. 결과는 절 단위로 구조 검증(H2 수, 위키링크, 코드블록)을 통과한 것만 반영되고, 실패한 절은 원본이 유지된다.

영역 노트를 만들었다면 같은 절차로 한 번 더 돈다. **raw는 humanize-korean에 넘기지 않는다.** 문장 정리는 Phase 1이 한계선 안에서 끝냈다. 윤문까지 돌리면 메모가 글이 되고 내용이 번진다.

## Phase 5 — 검증

```
python <skill-dir>/scripts/verify_digest.py --root <루트> --book <book> --chapter N
```

FAIL이 있으면 고치고 다시 돌린다. WARN은 보고에 그대로 싣는다. 이 스크립트가 잡는 것: 위키링크 해소, 절 지도 ↔ '넘어간 것' 일치(건너뛴 절이 없으면 절이 없어야 한다), '여기서 나온 노트'·'넘어간 것'이 빈 절인지, 정리본 코드의 줄이 전부 raw 코드블록에 있는지, raw 코드블록이 원본 백업과 같은지, 템플릿 안내문 잔재, 전사 비율(코드 제외), frontmatter·태그 형식, 소제목이 절 번호로 시작하는지, 책 index 행, 윤문 잔재 주석.

## Phase 6 — 보고

1. 만든/고친 파일 목록
2. '이 장에서 남은 것' 3~5줄 그대로 — 내가 고른 것이면 그렇다고 밝힘
3. 주장 절 제목 목록
4. **raw에 없던 것** — 보충한 문장, 채운 개념 정의, 고친 용어·사실. raw에 있던 것과 구분해서 적는다
5. '넘어간 것' 중 이유가 비어 있는 항목 → 질문
6. 영역 노트 후보 (있으면)
7. raw 정리 내역 — 원본 백업 경로, 고친 오탈자, 문장으로 정리한 메모 수, 고친 코드(전/후). humanize 변경률, verify 결과 한 줄
8. `draft: true` 상태와 커밋 제안. 커밋 메시지는 `docs(study): [<book>] chNN 정리본`. 커밋·푸시·draft 해제는 사용자가 시킬 때만 한다.

## 하지 않는 것

- 장 전체를 문장 단위로 옮겨 적어 정리본을 전사로 만드는 것
- 이 장이 건드리지 않은 노트로 링크를 뻗는 것, 빈 '여기서 나온 노트'·'넘어간 것' 절을 남기는 것
- 지어낸 코드·경험·"실제로 겪은 것" — 정리본 코드는 raw 코드블록 발췌뿐이다
- 정리본에 코드블록을 파일째 붙이는 것
- raw를 정리하면서 요약하거나 메모를 합치고 지우는 것, 없던 정보를 보태는 것
- raw 코드의 로직·구조를 고치는 것 — 줄 끝 공백, 코드블록 경계, 언어 태그, 붙여넣기 오류, 오타(보고에 전/후) 말고는. 일부러 틀린 예제(`// 오류:`)를 고치는 것
- 원본 백업 없이 raw를 정리하거나 `raw.original.md`를 덮어쓰는 것
- 시키지 않은 draft 해제·커밋·푸시
- 영역 노트 자동 생성
- index.md 큐레이션 문장을 승인 없이 밀어넣기 — 사람이 쓴 톤이 무너진다
- 절 목차를 확인 없이 확정

## Windows 메모

이 레포는 Windows에서 돈다. `python3`는 스토어 스텁이라 실패한다 — **`python`**을 쓴다. humanize-korean 문서의 shim 명령이 `python3`로 적혀 있으면 `python`으로 바꿔 실행한다. 파일은 LF(`.gitattributes`)·UTF-8이고, 스크립트는 둘 다 지킨다.
